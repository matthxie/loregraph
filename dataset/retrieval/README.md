# Retrieval evaluation dataset

A graded set of **68 retrieval questions with expected answers** over the *non-mixed*
test corpus — the 100 full Wikipedia articles (`dataset/wikipedia/articles.jsonl`,
ids `wiki_000`–`wiki_099`) and the 100 COCO photos (`dataset/images/manifest.jsonl`,
ids `img_000`–`img_099`). It is the hand-/machine-authored question file the eval
harness consumes via `load_questions` (see [`kg/evaluate.py`](../../kg/evaluate.py)),
complementing the two programmatically-derived tiers (`single_article` / `cross_article`).

Questions run from **simple single-fact lookups → multi-hop cross-document synthesis →
collection-wide aggregation**, so the set exercises the project's central thesis: that
graph traversal pulls in the connected documents a flat vector search misses.

## Files

| File | What |
|---|---|
| `questions.jsonl` | one JSON object per line, one question each (this dataset) |

## Record schema

```json
{
  "id": "q001",
  "query": "At which venue did Arlo Guthrie perform the 1997 live re-recording of his entire debut album, made 29 years after the original?",
  "kind": "lookup",
  "difficulty": "simple",
  "gold": ["obj_wiki_010"],
  "answer": "The Church in Housatonic, Massachusetts",
  "rationale": "Answerable only from wiki_010 …",
  "source": "authored+verified"
}
```

| Field | Meaning |
|---|---|
| `id` | stable question id (`q001`…`q068`), ordered simple → complex |
| `query` | the natural-language retrieval question a user would ask the graph |
| `kind` | question type (see taxonomy below) |
| `difficulty` | `simple` \| `medium` \| `complex` |
| `gold` | the **node ids that must be retrieved** to answer — minimal and complete |
| `answer` | the expected natural-language response, grounded strictly in the gold docs |
| `rationale` | why these gold docs / what retrieval behaviour the question tests |
| `source` | how the question was produced (see Provenance) |

The eval harness only reads `query`, `gold`, and `kind`; the other fields are extra
documentation/ground-truth and are ignored by `load_questions`, so the file stays
drop-in compatible.

### ⚠️ `gold` uses **node ids**, not corpus ids

Ingestion prefixes every object node id with `obj_` (`obj_wiki_010`, `obj_img_034` —
see [`kg/ingest.py`](../../kg/ingest.py) `base_id = f"obj_{item.id}"`), and that is
exactly what `KnowledgeGraph.query(...).object_ids` returns and what recall@k is scored
against. So `gold` here is `obj_<corpus_id>`. To recover the raw corpus id (and its
article/image file), strip the `obj_` prefix.

## Difficulty tiers

- **simple** — one gold doc, a single short fact. Tests seed/entry-point quality. The
  query describes the subject *obliquely* (never the article title verbatim) so retrieval
  has to do real work.
- **medium** — one gold doc, but answering needs understanding or synthesis of several
  facts within it, or a "find-the-document" need expressed without naming it.
- **complex** — **≥2 gold docs**, or a full-collection aggregation. Multi-hop /
  comparison / thematic questions that only score well if traversal recalls the whole
  connected set.

## Kind taxonomy

| `kind` | Tier | gold | Tests |
|---|---|---|---|
| `lookup` | simple | 1 | single-fact entry-point retrieval |
| `entity` | medium | 1 | multi-fact synthesis within one entity's article |
| `image` | simple/medium | ≥2 | image retrieval by a single visual object (COCO label) |
| `comparison` | complex | 2 | retrieve & contrast two same-category subjects |
| `multi_hop` | complex | ≥2 | traverse a shared entity/topic to a connected set |
| `image_multi` | complex | ≥1 | multi-object (intersection) image retrieval |
| `entity_mention` | complex | ≥2 | high-recall over every doc mentioning a shared entity |
| `thematic` | complex | ≥2 | collection-wide "which articles are about X" aggregation |

## Distribution (68 total)

- **By difficulty:** 23 simple · 14 medium · 31 complex
- **By kind:** lookup 16 · entity 12 · image 9 · multi_hop 7 · image_multi 7 · thematic 7 · entity_mention 6 · comparison 4
- **Modality:** 16 questions have image gold; 52 are text-only
- **Gold-set size:** 1 doc ×28, 2 ×13, 3 ×8, 4 ×8, 5 ×6, 6 ×3, 7 ×1, 9 ×1

## Provenance

Two construction methods, recorded in `source`:

- **`deterministic` (22)** — gold is *exact by construction*, not a judgment call:
  - **image** / **image_multi** (16): gold = every photo whose COCO object labels
    contain the queried object(s). A single label (e.g. *surfboard*) or an intersection
    (e.g. *person* AND *horse*).
  - **entity_mention** (6): gold = every article whose text literally mentions a shared
    entity (`\bEntity\b` substring), e.g. *American Civil War*, *World War II*,
    *Great Depression*, *South Korea*, *British Columbia*, *Russian Revolution*.
- **`authored+verified` (46)** — generated by a multi-agent workflow that (1) read all
  100 articles into a structured fact index, (2) found genuine cross-document clusters,
  (3) authored questions per tier, and (4) **adversarially verified each** against the
  source text — checking the answer is grounded, the gold set is complete and correct,
  the query doesn't leak the title, and the difficulty label fits. All 46 passed.

## Running the eval

```bash
python -m kg ingest --reset          # build the graph over dataset/wikipedia + dataset/images
python -m kg communities
python -m kg eval --questions dataset/retrieval/questions.jsonl
```

`kg eval` reports recall@k and MRR per retrieval mode (`ppr` / `bfs` / `vector`) and
breaks the numbers down per `kind` — so you can see directly where traversal beats flat
vector search (expected on `multi_hop` / `comparison` / `entity_mention` / `thematic`,
where the gold spans connected documents a single embedding lookup won't surface).

## Caveats

- **`entity_mention` is mention-recall, not "aboutness."** Gold is *every* article whose
  text contains the entity string, including incidental mentions. Contrast with the
  `multi_hop` American-Civil-War question (`q042`, gold `obj_wiki_022`+`obj_wiki_074`),
  which scopes to articles that *substantively engage* the war as their subject — the two
  are intentionally different and illustrate recall-vs-precision over a shared hub.
- **Images carry COCO object labels only** (no captions), so image questions are
  retrieval-by-depicted-object; they don't probe scene description or caption semantics.
- **Frozen corpus.** Gold ids assume the first, unversioned ingest of the frozen corpus
  (`obj_wiki_NNN` / `obj_img_NNN`). Re-ingesting changed content can create versioned
  ids (`…_v1`); re-derive gold if the corpus changes.
