# dataset/

Test corpus for the knowledge-graph prototype. Text and images are **independent** (not paired). Built by `scripts/build_dataset.py` via streaming (reproducible, fixed seed 42).

## Contents

- `wikipedia/articles.jsonl` — 100 random full Wikipedia articles (`{id, title, url, text, char_len}` per line). Source: `wikimedia/wikipedia` `20231101.en`, license **CC BY-SA 4.0** (attribution + share-alike).
- `images/*.jpg` + `images/manifest.jsonl` — 100 random real photos, ~640px, varied everyday subjects (`{id, file, source, label}` per line, `label` = COCO object categories). Source: `detection-datasets/coco`.
- `mixed/` — a **text-only** corpus: the Wikipedia articles **exploded into per-paragraph entries stamped over a timeline** (a synthetic event stream — see below), with hashed filenames. Each item is a `<hash>.txt` (**one paragraph** of an article, its section heading kept as the first line), so a directory listing **scatters an article's paragraphs in a basically-random order** instead of keeping them together. `mixed/manifest.jsonl` (sorted by `created_at`, a chronological stream) preserves the mapping: `{id (hash), file, modality, orig_id, title, url, label, para_index, para_count, created_at}`. Derived from `wikipedia/` (left untouched). **Images are intentionally excluded** — the knowledge graph is built from prose; `images/` is still used by the non-mixed `kg ingest` path and the retrieval eval. The entries are also **title-free body text**: the `title`/`url` in the manifest are provenance metadata only — `load_mixed` never injects the title into the item, so the Wikipedia article title never reaches the extraction prompt or a node name.

  **Per-paragraph temporal chunks.** Each Wikipedia article is split into paragraphs and **every paragraph becomes its own independent entry** with a fresh hashed name `sha1(orig_id#pNNN)[:16]` — so the chunks of one article scatter randomly through a directory listing rather than sitting together. Splitting (see `split_paragraphs`): blank-line blocks → drop the reference/category footer (everything from the first `References` / `See also` / `External links` / … heading onward) → fold a list-intro (`… the following:`) forward onto its items → fold a bare section heading backward onto the paragraph it titles → drop degenerate stubs (a heading with <3 words of body). This keeps ~94% of the article's characters (the rest is intentionally-dropped end-matter), so an entry is an actual prose paragraph, not boilerplate.

  Each entry carries a `created_at`. Within an article the paragraphs get **strictly-increasing** times (paragraph 0 oldest, later ones stamped later — so within an article `created_at` follows document order), and different articles start at different points in the window `[2023-11-01, 2026-06-01]`; sorting the whole manifest by `created_at` reads as a stream of paragraph-entries arriving over time. `para_index` + `para_count` let you regroup an article and recover order. Deterministic: hashes and timestamps (seeded RNG) reproduce exactly on re-run.

  **Scope of the "temporal" framing.** This is a *chronological append stream* — it spreads `created_at` over a timeline. It is **not** an update/contradiction stream: every entry is a distinct, never-restated fact, so nothing supersedes anything. The kg pipeline ingests this stream with `python -m kg ingest --mixed`: `load_mixed` reads the paragraph bodies and threads each entry's `created_at` (whose format matches `kg.store.now_iso()`) into the graph's `created_at` / `valid` machinery, instead of stamping every node with one wall-clock time.

Regenerate: `python scripts/build_dataset.py` (the two source folders), then `python scripts/build_mixed.py` (the combined `mixed/` folder).
